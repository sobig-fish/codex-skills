# 工作区账号登录与团队展示案例

把一个内部团队介绍页面的产品思路，整理成可以迁移到其他团队的技术方案：**先由可信平台确认登录身份，再由应用决定谁能看、谁能改。**

这是独立编写的教学案例，不是参考站点的源码镜像或登录服务。案例只包含合成资料，不包含真实员工、组织、站点地址、截图、凭据或私有标识。

核验日期：**2026-10-30**。

## 适合什么场景

- 团队成员介绍、职能导航和新人认识团队。
- 只向指定成员开放的活动入口或内部资料目录。
- 已有统一登录，需要补齐成员名单及管理员权限的轻量应用。

本案例把团队目录作为例子。平台登录、应用成员资格、资料访问范围是三个不同问题；登录成功不等于自动属于团队。

## 先看边界

| 内容 | 本案例状态 |
| --- | --- |
| 平台提供登录身份、服务端执行授权 | 已核对官方说明和本地 Sites 认证帮助函数 |
| 参考站点属于 Sites、目录显示工作区访问模式 | 已通过授权的只读平台查询确认 |
| 参考站点当前登录后界面、后台源码、数据库、OAuth 细节 | 本轮未取得，不能据此声称已还原 |
| 团队资料结构、角色矩阵、示例代码 | 本案例独立设计 |
| 示例的身份来源 | 明确标识的本地合成测试数据，不是真实 ChatGPT 登录 |
| 跨工作区分享 | 必须检查目标部署环境是否允许外部访客，不能统一承诺 |

详细证据见 [evidence-and-limits.md](./evidence-and-limits.md)。

## 运行示例

需要 **Node.js 22.18 或更新版本**。示例无第三方依赖，不需安装软件包，不启动网络服务，不请求任何账号权限。

在本案例目录执行：

```sh
node example/demo.mjs
node --test tests/policy.test.mjs
```

也可以直接在本案例目录执行 `npm test` 或 `npm run demo`。

演示包含成员查看合成目录、成员被拒绝管理名单、管理员获得管理权限、未加入名单的账号被拒绝，以及直接伪造身份对象被拒绝。演示会明确输出“本地合成身份，不是真实 ChatGPT 登录”。

## 复用时不要省略的条件

示例中的身份标记只能防止应用代码误把普通对象当成已解析身份，**它不是密码学认证，也不能保护错误配置的身份适配器**。真实部署必须先有可信平台会话或完成签名、签发方、受众、有效期等校验的身份验证器；不能把浏览器提交的请求头或 JSON 当成已登录用户。

平台访问权限、应用成员名单和连接器的数据权限应分别确认。分享一个网址，不会自动授予后两者。平台分享选项以当前账号、组织设置及实际功能开放情况为准。[官方分享说明](https://learn.chatgpt.com/docs/sites/publishing-and-sharing)
