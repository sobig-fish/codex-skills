# 合约游戏案例测试

把一个团队趣味预测需求，拆成可以复用的时间规则、互斥分类、历史参考算法和权限设计。

这里的“事件合约”只是界面与交互形式：参与者对一个将来公布的事件数量保存判断，管理员确认实际结果后显示是否命中。**没有购买、转让、兑换或奖励，不是真实金融合约，也不产生奶茶、现金或其他可兑现权益。**“奶茶模拟倍率”仅用于展示历史类别的相对稀有程度。

本目录公开的是经过抽象的纯算法代码、虚构数据、演示脚本与设计文档。它**不是完整生产应用源码**：不包含真实业务记录、账号、部署凭据、数据库实例、平台身份接入或站点管理设置。将这些文件放到 GitHub，也不会自动获得 GPT 账号登录能力。

## 先运行，再看设计

需要 **Node.js 22.18 或更新版本**，以及可用的 npm。此案例没有第三方运行依赖，不需要执行 `npm install`。

这里使用 Node.js 内置的 TypeScript 类型擦除能力运行可擦除语法；它从 22.18 起默认启用，**不会执行 TypeScript 类型检查**。运行测试与静态类型检查不是同一件事。[Node.js 官方说明](https://nodejs.org/api/typescript.html)

在仓库根目录执行：

```sh
cd "cases/合约游戏案例测试"
npm test
npm run demo
```

`npm test` 运行本地纯算法测试；`npm run demo` 使用虚构历史数据演示规则和参考计算。具体输出与是否通过，以当前代码在你本机的运行结果为准。这些命令不会访问公司系统或真实业务表格，也不会创建在线站点。

## 一期活动怎样进行

下面的日期与人数仅用于说明规则，是独立的虚构例子，不代表任何真实活动。

假设预测的是 **2030 年 1 月 7 日所在周**的事件总量，分类阈值为 **7**。全部时间采用北京时间（UTC+8）。

| 环节 | 虚构例子的时间 | 规则 |
| --- | --- | --- |
| 管理员审核 | 上周三 2030-01-02 11:00 至 12:30 前 | 审核分类阈值与参考数量；12:30 起不能继续修改设定 |
| 开放选择 | 上周三 2030-01-02 12:30 起 | 只有在审核窗口内通过审核的期次才能开放 |
| 截止选择 | 上周四 2030-01-03 18:00 | 18:00 起拒绝新增或修改选择 |
| 业务发生 | 当周一与当周三 | 记录实际完成数量，临时变化不提前当成最终结果 |
| 人工确认 | 当周三 2030-01-09 11:00 之后 | 管理员确认实际总量；系统才更新命中判定 |

到达结果确认时间，表示“可以确认”，不表示“已经知道结果”。没有管理员的有效确认，页面继续等待。

每个参与者每期只有一份选择，截止前可以修改，最后一次有效提交覆盖前一次。原应用另要求先确认当前规则版本。错过审核窗口的期次不会自动补发；异常期次可在结果确认前取消。

## 四个答案必须互斥

以虚构阈值 7 为例：

| 类别 | 含义 |
| --- | --- |
| `zero` | 0 |
| `below` | 1–6 |
| `equal` | 7 |
| `above` | 8 及以上 |

不能同时使用“0”和“小于 7”作为两个独立答案，否则 0 会同时命中两个类别。代码要求阈值至少为 2，避免产生空的“1 到阈值减 1”区间。

## 奶茶模拟倍率是什么

```text
展示倍率 = min(20, 1 ÷ 历史参考比例)
```

倍率保留两位小数，按未取整的参考比例计算。例如，虚构比例 25% 对应 4.00×，虚构比例 2% 因显示上限而对应 20.00×。上限可能让不同选项显示相同倍率；这不代表它们的参考比例相同。

没有有效样本、比例无效或比例不大于 0 时，不显示倍率。空数据情况下算法里的占位值和展示先验不能被解释为真实预测。

**倍率不是收益率、奖品数量、价格或兑现承诺。**本案例没有余额、下单金额、输赢账户、奖励发放或支付结算。

## 历史数据能提供什么

算法选取审核开始前按业务时间应已确认的历史周，将近期有记录的周与往年同月日前后时段合并，生成描述性比例、均值、历史范围及有限的回看误差参考。细节见 [历史参考算法](./architecture.md#历史参考算法)。

必须保留这些限制：登记数量可能不同于实际完成数量；无记录不等于 0；历史补录时间可能未知；流程、人员安排、节假日等变化会让旧分布失效。参考比例不能证明未来事件具有同样的真实发生概率。

## 哪些思路可以复用

| 场景 | 可以复用的部分 | 需要重新定义的部分 |
| --- | --- | --- |
| 活动人数预测 | 时间窗口、四类选择、人工确认、个人记录 | “报名”“到场”“完成参与”的统计口径 |
| 报名统计练习 | 只读历史汇总、缺失与零值区分 | 取消、重复报名、补录如何处理 |
| 服务容量演练 | 历史参考、版本锁定、并发写入检查 | 业务容量与故障阈值；不能把娱乐倍率当容量保证 |

要做成可供多人使用的真实网站，还需要独立实现认证、授权、存储、审计、运维与目标平台部署。不要把本地测试通过等同于这些环节已经完成。
